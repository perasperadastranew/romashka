01 / 07 · ИДЕЯ

Долина как коттеджный посёлок

Ромашковая долина и так устроена как посёлок: у каждого героя свой дом, свой участок и свой характер. Мы просто назвали это вслух. Сайт стал генпланом, домики стали лотами, а описания написаны языком риелтора: «Мох на крыше входит в стоимость и растёт бесплатно».

Такая рамка сразу решила структуру. Один экран на один лот, карточка с названием, коротким текстом и одной кнопкой, которая что-то крутит в доме. На финале все лоты проданы.

Листай карточки ниже: камера сама перелетает от лота к лоту и разворачивается к фасаду, как на сайте.

02 / 07 · МОДЕЛИРОВАНИЕ

Домики из мультфильма в Blender через MCP

Готовых 3D-моделей не было, поэтому каждый дом собирали заново по кадрам мультфильма. Blender подключён к Claude через MCP: Claude видит сцену, пишет Python-код для Blender и сразу проверяет результат по скриншоту.

  1. Референсы. 3–4 кадра дома с разных сторон. Чем понятнее силуэт на кадре, тем меньше правок потом.
  2. Блокинг примитивами. Сначала цилиндры, кубы и сферы в правильных пропорциях. Детали только после того, как силуэт совпал.
  3. Детали и материалы. Окна, черепица, плющ, заборы. Материалы матовые, цвета как в мультфильме.
  4. Подвижное отдельно. Ромашка на двери, лопасти мельницы, флаг, вентиль — отдельные объекты с точкой вращения. Их потом крутит код сайта.
  5. Экспорт. Тело дома и каждая подвижная деталь уходят в свой glTF-файл.

Где ускорить

Один дом — одна сессия. Когда в сцене один объект, Claude не путает имена и не ломает соседей. Сразу договоритесь о масштабе (1 юнит = 1 метр) и о том, что начало координат стоит у основания дома: тогда сборка карты сводится к трём числам на дом.

04 / 07 · ПРОЛЁТ КАМЕРЫ

Сначала облёт, потом изометрия

Первая версия летала вокруг каждого дома по кругу, как дрон. На словах звучит кинематографично, а в браузере выглядело не очень: горизонт всё время качается, дома разного размера то лезут в камеру, то теряются, и глазу не за что зацепиться.

В итоге оставили ортографическую камеру. Она всегда смотрит под одним углом, как на генплане, и только сдвигается и приближается от дома к дому. Переключи режимы и сравни на тех же моделях.

05 / 07 · ВЕБ-КОДИНГ

Правила, которые держат 3D лёгким

Сайт — один index.html и папка с моделями. Никакой сборки: файлы лежат на GitHub Pages как есть. Вот что из кода стоит забрать в свои проекты.

01 · Части отдельно

Тело и подвижные детали в разных файлах

Деталь висит на своей точке вращения (pivot), её крутит код. Анимации в Blender не нужны, а кнопка «Крутануть ромашку» — это три строки.

02 · Дорожки без геометрии

Маска вместо тысяч полигонов

Дорожки, газоны и вода нарисованы одной картинкой paths.png на 173 КБ. Шейдер земли читает её каналы и красит поверхность.

03 · Инстансы

Сотни цветов одним вызовом

Цветы, кусты, камни и фонари — InstancedMesh. Тысяча ромашек стоит видеокарте как одна.

04 · Без карты окружения

Блики нарисованы в шейдере

Отражение неба на стекле и металле — пара строк в шейдере материала вместо тяжёлой HDRI.

05 · Тени облаков

Невидимые сферы

Облака не рисуются, они только отбрасывают тень. По долине бегут пятна, а вид на дома ничего не закрывает.

06 · Бесконечная долина

Земля повторяется зеркально

Одна модель земли клонируется сеткой 5×5 с отражением. Край карты не виден, а геометрия в памяти одна.

07 · Погода шейдером

Снег ложится сверху

Снег покрывает только поверхности, которые смотрят вверх, дождь слегка темнит всё. Ни одной новой модели.

08 · Потолки

Плотность пикселей не выше 2

pixelRatio ≤ 2, одна карта теней 2048, текстуры без мипмапов. На ретине разницы не видно, а телефон не греется.

paths.png · три канала = три слоя
Вес моделей · МБ

Следующий шаг

Модели лежат как glTF в JSON, около 30 МБ на всю долину. Сжатие геометрии Draco или meshopt обычно уменьшает такие файлы в несколько раз. Это первое, что стоит сделать перед боевым запуском.

06 / 07 · REACT И КОНЦЕПЦИЯ

Как такое собирают на React и откуда берётся идея

Наша долина написана на чистом three.js в одном файле: так быстрее всего начать, и Claude легче держать весь код в голове. Когда проект растёт (много экранов, общее состояние, контент из CMS), студии переходят на React и React Three Fiber. Там 3D-сцену описывают так же, как интерфейс: компонентами.

Суть React в одной фразе: интерфейс — это функция от состояния. Ты меняешь состояние «активный лот = 3», а React сам перерисовывает карточку, кнопку и камеру. Вручную ничего не ищешь и не обновляешь.

Как у нас · three.js
// создать, загрузить, добавить, обновлять в цикле
const g = new THREE.Group()
g.position.set(h.x, 0, h.z)
loader.load('map/PinkHouse.json', gl => g.add(gl.scene))
scene.add(g)
function frame(){ daisy.rotation.z += .01 }
То же на React Three Fiber
function House({ file, x, z, rot }) {
  const { scene } = useGLTF(`/map/${file}.glb`)
  const daisy = useRef()
  useFrame((_, dt) => daisy.current.rotation.z += dt)
  return <primitive object={scene} position={[x, 0, z]} rotation-y={rot} />
}
<Canvas>{houses.map(h => <House key={h.file} {...h} />)}</Canvas>
01 · Дом = компонент

Один файл на один дом

<House> получает координаты и модель. Девять домов — это девять строк в массиве, а не девять копий кода.

02 · drei

Готовые помощники вместо велосипедов

Библиотека drei даёт useGLTF (загрузка с кэшем), OrthographicCamera, ScrollControls (скролл двигает камеру) и Html для подписей прямо в 3D.

03 · Модель → код

gltfjsx делает из модели компонент

Команда npx gltfjsx house.glb превращает модель в JSX, где у каждой детали есть имя. Ромашку на двери сразу видно и можно крутить.

04 · Общее состояние

Один стор на сцену и интерфейс

Активный лот и погода лежат в маленьком сторе (zustand). Кнопка в DOM и камера в 3D читают одно и то же значение, поэтому не расходятся.

05 · Главная ловушка

Не гонять setState 60 раз в секунду

Анимацию делают в useFrame через ref, напрямую меняя объект. Через состояние React будет перерисовывать всё дерево каждый кадр, и сайт задохнётся.

06 · Загрузка по мере пролёта

Suspense и preload

Дальние домики подгружаются, пока камера летит к ближним. Первый экран открывается быстро, а 30 МБ моделей не встают в очередь сразу.

07 · Старт с Claude

Сначала пустая сцена, потом по компоненту

Промпт: «Сделай проект Vite + React + React Three Fiber: один дом из GLB, тени, ортографическая камера». Когда это работает, добавляй по одному: землю, второй дом, скролл, кнопку.

08 · Когда React не нужен

Один экран — можно без него

Если сайт — одна сцена и пара кнопок, чистый three.js проще и легче. React окупается, когда экранов и состояний становится много.

Как придумать такую концепцию

  1. Найди рамку из жизни. Не «сайт про героев», а «коттеджный посёлок». Рамка сразу даёт структуру (лоты), язык текстов (риелтор) и шутки («мох растёт бесплатно»).
  2. Один экран — одна мысль. Лот, карточка, одно действие. Если на экране три кнопки, пользователь не нажмёт ни одну.
  3. Дай объекту телесное действие. Крутануть ромашку, раскрутить лопасти, качнуть тыкву. Маленький отклик запоминается лучше длинного текста.
  4. Стиль из ограничения. Одна камера под одним углом стала почерком сайта. Ограничь себя: один ракурс, одна палитра, один тип движения.
  5. Проверь идею на кубах. За вечер поставь белые кубы на места домов и сделай пролёт камеры. Если на кубах не цепляет, модели не спасут.
  6. Смотри, как делают другие. Портфолио Bruno Simon (машинка по 3D-миру), сайты с наградами Awwwards в разделе WebGL, игры вроде Monument Valley для изометрии.
Промпт для старта концепции

«Вот тема: [что показываем]. Предложи 5 метафор из реальной жизни, через которые это можно показать на сайте. Для каждой: структура экранов, одно действие пользователя на экран и тон текстов».
